# 0011 ガードレールに、引き継ぎ・ひとりでのレビュー・改行のそろえを足す

- 日付：2026-11-28
- 背景：0001 のガードレールを入れてから、機能が増え、Worker も2つになった。次のことに困っていた
  - Windows で全ファイルが CRLF になり、手元の `format:check` が落ちる
  - 確認のコマンドがばらばらで、「何が通れば出してよいか」が1つにまとまっていない
  - セッションをまたぐと、本番の状態（何を流し、何をデプロイしたか）が分からなくなる
  - ひとりで開発しているので、PR を作った本人以外の目が入らない
- 決定：
  - `.gitattributes` で改行を LF にそろえる
  - `npm run check`（整形・lint・knip・型・テスト・2つの Worker のバンドル）と `npm run build` を足し、CI のビルドも `npm run build` にする。CI では git フックを入れない（`LEFTHOOK: 0`）
  - `docs/HANDOFF.md` を置き、作業の初めに読み、終わりに更新する。本番の状態は確かめた日付つきで書く
  - CLAUDE.md に「書き方の例」「本番」「レビュー」の節と、PR を小さくする目安（150行）を足す
  - レビューは、CI → PR を作った会話の記憶を持たない Claude の `/code-review` → ユーザーが差分を読む → 本番のデータ・鍵・認証・移行 SQL に関わるものは一晩おく、の順
  - `.claude/settings.json` の `.env`・`.dev.vars` の読み取り禁止を、サブフォルダ（`mcp/.dev.vars` など）にも広げる
  - PR テンプレートに、レビューと「本番に出すとき」（移行 SQL・2つの Worker のデプロイ・HANDOFF の更新）のチェックを足す
- 理由：
  - 改行がそろわないと、整形の検査が手元と CI で食い違い、検査を信じられなくなる
  - 作った本人は経緯を知っていて同じ思い込みを持つので、経緯を知らない Claude に読ませる方が抜けが見つかる
- 代替案（入れなかったもの）：
  - GitHub Actions での承認つきデプロイ：ユーザーが手でデプロイする今の手順で回っているので、今は入れない。入れるなら Cloudflare の API トークンを Secrets に置き、`check`（鍵があるか）→ `plan`（移行 SQL と入る内容を Summary に）→ `deploy`（`environment: production` の承認待ち）の形にする
  - 本番に触るコマンドを禁止（deny）から確認（ask）に緩める：0001 のとおり、本番は人の手に残す
  - lint の独自ルール：AI が同じ癖を繰り返していないので、出てから足す
  - PR ごとに Claude に自動でレビューさせる：API の料金がかかる。手で `/code-review` を回して、手間に感じたら考える
