# 0016 MCP サーバーにつなげる AI アプリと人を限る

- 日付：2026-11-28
- 背景：Gemini と Muse からもつなげた。そのあと Muse による外からの診断と、別の Claude によるコードの確認で、次が分かった
  - アプリの登録（DCR）はだれでもでき、名前も自由。偽の「Claude」を登録して許可のリンクを送り、許可させれば、家計簿を読める。書き込みのチェックが初めからオンなので、書き込みまで渡りやすい
  - `send_feedback` が書き込みのツールの一覧になく、読み取りだけの許可で文を残せた。残した文は `get_usage_insights` でほかの AI が読む
  - だれの LINE でもログインでき、自分の空の家計簿ができる（ほかの人の家計簿は見えない）
- 決定：
  - ログインのあとに戻ってよい先を、URL 全体で決める（`mcp/access.ts`）。Claude（`https://claude.ai/api/mcp/auth_callback` と claude.com）と Muse（`https://agent.meta.ai/api/hatch/oauth/callback`）はコードに書く。Gemini の戻り先（`https://oauth-redirect.googleusercontent.com/r/<ID>`）は Google アカウントごとに違い、個人の ID を含むので、シークレット `EXTRA_REDIRECT_URIS` に持ち主の分だけ入れる。ほかは許可の画面も出さない。許可の画面の前と、トークンを出す直前の両方で確かめる。DCR と CIMD のどちらのアプリもこの確認を通る
  - AI とつなげるのは、シークレット `OWNER_LINE_USER_ID` の LINE アカウントだけにする。ログインのあとと、毎回の呼び出しの両方で確かめる。設定がなければ、だれも通さない
  - 許可の画面の「書き込み」は、初めはオフにする
  - `send_feedback` は書き込みの許可が要るツールにする。読み取りでないツール（`readOnlyHint` が true でない）はすべて書き込みの一覧にあることを、テストで確かめる
- 理由：
  - 戻り先を限れば、偽のアプリに許可しても、トークンは本物の AI アプリにしか届かない。名前を見分けるより確か
  - ドメインだけで比べると、ほかの人が自分の Gemini でつないだ戻り先（同じドメインで、パスだけ違う）も通ってしまう。そうすると、偽のリンクから持ち主が許可したトークンが、その人の Gemini に届く（PR #33 のレビューで見つかった）
  - 持ち主だけにすると、ほかの人がこのサーバーを使えなくなる（D1・KV の無料枠や要望の送信を使われない）。ログインした人だけが試せる穴を、今後うっかり作っても、突ける人がいない。AI とつなぐのは持ち主だけなので、失うものはない（2026-11-28 にユーザーが自分専用を選んだ）。家計簿のボット自体は、今までどおりだれでも使える
  - 偽のアプリに許可させる手口は、持ち主だけにしても防げない（だまされるのは持ち主なので）。これは戻り先を限ることで防ぐ
  - userId は個人の情報なので、公開リポジトリの `[vars]` に書かずシークレットにする
- 代替案：
  - DCR を止める：Gemini・Muse がつなげなくなる
  - 許可の画面で戻り先を目立たせるだけ：見落とせば渡ってしまう
  - 許可の一覧と取り消しの画面：今は持ち主だけなので後回し。要るようになったら `listUserGrants`・`revokeGrant` で作る
- 残したこと：
  - 登録のレート制限はない（Cloudflare のルールで足せる）。診断で作られたテストの登録は、使われなければ90日で消える
  - この変更より前に、持ち主でない人が受け取った許可とリフレッシュトークンは KV に残る。呼び出しはすべて 403 になり、使われなければ期限で消える
  - Claude と Muse の戻り先は、だれのつなぎでも同じ URL。だれのつなぎかは、AI アプリの側が state などで見分ける。そこはこちらからは確かめられないので、自分でつなごうとしたときだけ許可する
