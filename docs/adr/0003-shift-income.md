# 0003 シフト収入を Google カレンダーの非公開iCalから計算する

- 日付：2026-11-27
- 状態：カレンダーをバイト先ごとに分ける部分は、0005 でひとつのカレンダーに変えた
- 背景：バイトの給料日と金額の見込みを、家計簿と同じ場所で見たい。GAS 版のプロトタイプで計算ロジックは確かめてあり、それを kakeibot に移す
- 決定：
  - シフトは Google カレンダー（バイト先ごとに1つ）に入れ、Worker から「iCal 形式の非公開アドレス」を fetch して読む。OAuth は使わない
  - 計算ロジックは GAS 版の `Calc.gs` をそのまま移し（`src/shift/calc.ts`）、GAS 版で確認済みの期待値を単体テストにする
  - 繰り返し予定の展開には `ical.js`（Mozilla、依存なし）を使う。ただし1件あたりが重いので、繰り返しのない予定は自前で読み、ical.js には繰り返しと自前で読めない形だけを渡す。毎日・毎週の繰り返しは、開始日を周期の倍数だけ期間の直前まで進めてから展開する
  - 読む期間は、表示する年の前年9月からその年の年末まで（翌々月払いと年間の支給額に要る分）
  - 非公開URLは AES-GCM で暗号化して D1 に置く。鍵は wrangler secret の `ICAL_ENCRYPTION_KEY`。API からは「登録済みか」しか返さず、ログにも出さない。受け付けるのは `https://calendar.google.com/calendar/ical/` で始まる URL だけ
  - 祝日は holidays-jp の年別 JSON を使い、Cloudflare に1日キャッシュさせる
  - LIFF は家計簿とは別のページ `/app/shift` にする（同じ LIFF ID の下の階層）
- 理由：
  - 非公開URLなら、ユーザーは URL を貼るだけで済み、OAuth の審査やトークン管理がいらない
  - URL を知っていれば誰でもシフトを読めるので、D1 の中身だけが漏れても読まれないよう暗号化する。シークレットに URL 自体を置く方法だと、設定画面から登録できず、使えるのも1人だけになる
  - Workers の無料プランは CPU 時間が1回 10ms まで。架空のカレンダーで測ると、ical.js で全部を読むと 60ms ほどかかった。自前の読み取りと期間の絞り込みで、単発のみ2年分（約280件）が 1.9ms、単発3年分と毎週の繰り返し1本で 4.5ms になった
  - Google の日本の祝日カレンダーには、節分などの祝日でない日も入っている。holidays-jp は祝日・振替休日・国民の休日だけで、年別の JSON が数年先まである
  - `app.html` はすでに700行あり、別ページに分けた方が読みやすい
- 代替案：
  - Google Calendar API（OAuth）：期間を指定して取れて軽いが、OAuth の同意画面とトークンの保存・更新が要る
  - `node-ical`：Temporal の polyfill に依存していて重い。`rrule` は iCal 本体を読む部分を自前で書くことになり、更新も止まっている
  - 繰り返しの展開も自前で書く：速いが、RRULE の細かい規則で漏れやすい
- 注意：毎週の繰り返し予定が何本もあるカレンダーでは、ical.js の展開だけで 10ms を超えることがある（5本で約 19ms）。超えるようなら、Workers の有料プランにするか、Cron で展開済みのシフトを D1 にためる方式に替える
