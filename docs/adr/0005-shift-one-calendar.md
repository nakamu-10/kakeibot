# 0005 シフトはひとつのカレンダーに入れ、予定のタイトルでバイト先に振り分ける

- 日付：2026-11-28
- 背景：0003 ではバイト先ごとにカレンダーを1つ作り、それぞれの非公開アドレスを登録する方式にした。実際に登録してみると、カレンダーを作ってアドレスをコピーする作業をバイト先の数だけ繰り返すのが手間だった
- 決定：
  - 非公開アドレスはユーザーに1つ（`shift_settings.ical_url_enc`）。暗号化のしかたは 0003 のまま
  - バイト先ごとに「予定のタイトルに含まれる言葉」（カンマ区切り）を持ち、空ならバイト先の名前で判定する
  - 複数のバイト先に当てはまるときは、長い言葉で当たった方にする（家計簿のカテゴリのキーワード判定と同じ）
  - 全角・半角、大文字・小文字の違いは NFKC と小文字化でならす
  - どれにも当てはまらない予定は数えない。その月のタイトルを収入タブに出し、書き忘れに気づけるようにする
  - 既存DBは `migrations/0002_shift_one_calendar.sql` で、各ユーザーの1つ目のバイト先に登録したアドレスを引き継ぎ、バイト先ごとのアドレスの列は消す
- 理由：
  - 予定を作るときにタイトルを書くのは自然で、手間が増えない
  - カレンダーを読むのが1回で済み、fetch とパースの CPU 時間も減る
  - 当てはまらない予定を数えないので、私用の予定と同じカレンダーに入れても給料に混ざらない
- 代替案：
  - バイト先ごとのカレンダーとひとつのカレンダーの両方を選べるようにする：設定と画面が複雑になる
  - 予定の色で振り分ける：iCal の非公開アドレスには色の情報が入らない
